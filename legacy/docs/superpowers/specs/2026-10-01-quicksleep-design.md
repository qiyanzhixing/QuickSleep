# QuickSleep 双平台设计说明

日期：2026-10-01  
状态：待审阅；尚未开始产品代码、依赖安装或仓库推送

## 目标

制作自用、离线运行的 Android 和 iOS 助眠应用。沿用已确认的 Figma 深色、浅色和声音模式设计，首页只保留助眠总时长与声音模式两个主要选择。首版提供简体中文和英语，所有界面文字、声音说明、呼吸引导和系统播放器信息均随语言切换。

## 首版范围

- 总时长：5、10、15 分钟和自定义，首次默认 10 分钟
- 声音：月下轻语、山间静心、林间晚风；声音与背景预先混合，没有独立音量滑杆
- 开始后固定进行 4 轮 4–7–8 呼吸引导，然后保持背景声音并恢复自然呼吸
- 总时长包含引导与最后 15 秒淡出；结束后保持安静，不提示、不自动重播
- 支持锁屏和后台播放、暂停、继续、结束；电话打断或耳机断开后暂停
- 支持跟随系统的主题与语言，以及独立设置页中的手动覆盖
- 不引入账号、网络内容、广告、订阅、统计、睡眠评分或用户可选轮数

## 建议采用的默认行为

以下是为首版明确的可调整默认值：

- 自定义时长为 2–60 的整数分钟；非法、空白、小数和越界输入不保存
- 每个呼吸计数间隔为 1 秒；4 轮共 76 秒，随后 4 秒轻声提示恢复自然呼吸
- 暂停期间不消耗剩余时间；来电和耳机断开后必须手动继续
- 结束立即停止并回到准备状态；重新开始是一段新的完整练习
- 主题、语言、声音模式与时长保存在本机；首次声音默认为月下轻语
- 系统语言为中文时使用简体中文，否则使用英语；可手动选择中文或 English
- 一段已开始的练习固定其语言、模式和时长；设置更改作用于下一次练习
- 试听为 8 秒的本地示例；同一时刻只播放一个，关闭选择页即停止，开始练习前也停止
- 系统强制结束应用后不自动恢复播放

## 技术选择

推荐 Flutter 和 Dart，一个界面与业务代码库交付两个原生应用。音频使用 just_audio、audio_service、audio_session；本地设置使用 shared_preferences；语言使用 Flutter 本地化资源。具体版本在实际安装后锁定，并提交依赖锁文件。

备选方案：React Native 和 Expo 便于利用当前 Node 环境，但精确的后台结束与淡出仍需可靠的原生调度；分别使用 Swift 与 Kotlin 则需要维护两套界面和逻辑。Flutter 的原生音频队列、裁剪和打断处理与本应用较匹配。

职责划分：

1. SessionPlan：纯 Dart，生成有限播放序列，计算全局进度、呼吸阶段和剩余时间
2. SessionAudioHandler：唯一音频所有者，统一接收页面、锁屏和系统打断事件
3. 页面：准备页、声音选择页、自定义时长页、练习页、设置页；只渲染和发出用户操作
4. Preferences：保存设置、解析系统主题和语言，不保存敏感个人信息
5. AudioCatalog：声明各语言、模式的本地文件、时长、来源、校验值和授权记录

## 锁屏与计时设计

不用界面定时器决定何时切换音频或停止。开始前构造完整且有限的原生播放队列，关闭重复与随机播放；界面计时来自实际媒体播放进度。

对于整数时长 M 分钟，队列为：

- 80 秒引导音频：76 秒呼吸计数和 4 秒自然呼吸过渡
- M−2 段各 60 秒的背景音频
- 同一背景音频开头的 25 秒片段
- 15 秒预先制作的淡出尾段

总时长为 80 + 60×(M−2) + 25 + 15 = 60M 秒。淡出尾段使用背景第 25–40 秒的同一波形，并逐渐降至静音。引导末尾、背景循环边界和尾段必须保持连续，试听和实际音轨都需要听感检查。内部背景素材的重复用于铺满本次时长，不会重复整段练习。

Android 配置媒体播放前台服务与通知；iOS 配置后台音频。锁屏显示整段练习的标题、总时长和全局进度，只开放播放、暂停和停止。系统打断统一转换为暂停，不在打断结束后自行继续。

## 实际音频交付

全部成品音频随应用安装包提供，首次启动即可断网使用。应用运行时不调用在线语音服务，也不依赖手机是否安装某种 TTS 语音。

首版音频由构建工具提前生成：从官方 hexgrad/Kokoro 开源工具及对应模型生成中文、英语计数和引导，再用 Python、NumPy 和 ffmpeg 生成原始背景与混音。手机只包含音频成品，不包含模型和生成引擎。

- 月下轻语：轻柔风格合成女声，加原创柔和氛围背景
- 山间静心：沉稳风格合成男声，加原创古琴风格合成拨弦背景
- 林间晚风：自然轻声风格合成语音，加原创风声与树叶质感背景

生成声音必须清楚标注为合成；古琴风格合成拨弦不能标作真实古琴演奏。模型与具体语音授权、来源和生成参数需随仓库保存，避免复制未知来源的音乐。Kokoro 英语与普通话都有男女声可选，但其官方文档明确提示短语和非英语效果存在差异；中文优先评估 1.1-zh 模型。每种语言和模式都必须试听，未通过发音与节奏检查的素材不能冒充成品。

素材生成是首个实施验证点：必须产出可播放、非空、无削波、具有正确时长的六套引导与试听，以及三套背景和尾段，才接入应用。若模型下载或生成失败，报告具体阻碍，不提交缺失文件的运行版本，也不静默替换为联网 TTS。

深色主色：背景 #080D1B，表面 #131A2C，强调 #B6A2EF，文字 #E9E5FB。浅色主色：背景 #F7F4F0，表面 #EDE7EF，强调 #78618F，文字 #332C3F。以 Figma 变量模式与截图为依据，不能把浅色代码中的深色回退值当作浅色设计。

使用 Noto Serif SC 与 Noto Sans SC 的授权本地字体，以及设计导出的本地静态素材。布局适应设备安全区域和较大文字；不会把设计图里的固定时间、状态栏、屏幕边框或手势条绘制成假系统界面。呼吸球跟随媒体进度：吸气放大、屏息保持、呼气缩小；自然呼吸阶段不再计数。减少动态效果设置下使用静态状态变化。

中文和英语资源使用相同的键，不把业务判断写成某一种语言的文字比较。英语模式名称暂定 Moonlit Whispers、Mountain Stillness、Forest Evening Breeze。设置页提供语言和主题，避免在首页增加主要选择。

## 验收标准

1. 所有 2–60 分钟计划恰好包含 4 轮呼吸和最后 15 秒淡出，总媒体时长等于所选时长
2. 暂停、系统打断和恢复后，画面、语音与剩余时间一致；不存在计时继续但声音停止的状态
3. 两种语言、两种主题和三种模式均可断网首次运行，没有缺失音频或联网字体
4. 连续点击开始、反复试听、关闭选择页和来回切换页面，不产生重叠播放
5. Android 和 iOS 真机锁屏至少完整播放一次 10 分钟练习，验证最后淡出与停止
6. 真机验证电话打断、有线耳机断开与蓝牙断开；无耳机设备可将不适用项明确记录
7. 静态检查、单元测试、界面测试、音频素材校验与平台构建分别列出结果，不把未执行当作通过
8. 推送后验证远端提交编号，并检查该提交对应的持续集成结果

## 当前仓库与验证限制

[仓库](https://github.com/qiyanzhixing/QuickSleep) 为公开仓库，main 当前只有 README.md 和 Xcode 模板 .gitignore；基线提交为 fd589857403951fc664697bf6847330ed12bbd4c。没有现成应用代码需要迁移。

已验证 GitHub 连接具备推送权限，HTTPS Git 读取成功。SSH 读取被当前环境系统 SSH 配置错误阻断，可以通过已连接的 GitHub 发布接口提交代码与二进制素材；无需索取或读取密钥。

当前 Linux 环境有 Node、Python、NumPy、ffmpeg 和 Java 运行时，尚无 Flutter、Dart、Java 编译器、Android SDK、Gradle、Xcode或语音生成模型。Flutter 源代码可访问，但测试的官方 Linux 发布目录返回 404；尚未验证 SDK 安装可行。后续优先补齐可用工具链，否则使用仓库持续集成并准确披露限制。

iOS 不能在此 Linux 环境用 Xcode 构建或模拟器验证。可准备 macOS 持续集成构建；个人手机安装所需签名、证书、Apple 账号和真机测试仍需要可用的 macOS 环境及相应授权。Android 构建也要等 SDK 和编译器配置实际成功后才能承诺产物。
